# v1.7.0 — 로컬 AI detector 교차 검토

2026-10-03. 사용자가 설치한 `bilingual-ai-detector`의 **v3.1 실행 계약**을 확인하고, humanizer와 번갈아 사용하는 절차를 구현·실행했다. 작업 중 탐지기 문서 버전이 v3.1.1로 갱신됐으나 실행 코드는 같았다. 마지막 사용자 요청에 따라 로컬 탐지기가 설치된 일반 재작성은 탐지부터 시작하는 기본 흐름으로 정했다. 최소 교정·검토 전용 작업과 탐지 없는 편집 요청은 이 기본값에서 제외된다. **연결 기능과 검토 절차는 검증했지만 탐지 점수의 전반적 향상은 입증하지 못했다.** 탐지기 자체, 모델 가중치, 보정값은 바꾸지 않았다. 상용 API·서비스 결제·새 계정·모델 다운로드는 없었다.

## 변경한 기능

1. 원고의 정확한 바이트와 해시를 고정하고, 설치된 탐지기의 문단 색인·로컬 측정·실행 기록을 저장한다.
2. 모든 문단을 읽고, 정확한 인용과 인간 작성으로도 설명 가능한 이유를 포함한 detector ledger를 작성한다. 숫자 결과만으로 이 단계를 대신하지 않는다.
3. 피드백을 `revise`, `retain`, `unresolved`로 판단한다. 실제 독자 문제가 있는 곳만 수정하고, 필요한 정보나 장르상 자연스러운 표현은 유지한다.
4. 수정본 전체를 최초 원문과 대조한 뒤 다시 측정하고 검토한다. 더 높은 점수라도 의미가 바뀌면 채택하지 않는다. 원문·후보·복구본과 각 판단을 남긴다.
5. 탐지기 실행 실패는 확률 `null`로 보존한다. 영어의 Humanized·AI-edited를 Human에 합하지 않으며, 긴 영어의 문서 확률 부재도 그대로 유지한다.

스킬의 최대 수정 회차를 늘리지 않았다. [절차와 명령](../../skills/bilingual-humanizer/references/local-detector-loop.md), [새 연결 도구](../../skills/bilingual-humanizer/scripts/local_feedback.py), [독립 도구 검토](adapter-review.md).

### 도서관: 높은 점수의 의미 오류를 거부

탐지기 검토는 가까이 반복되는 두 표현을 편집 후보로 제시했다. 첫 수정본은 Human이 1.6474%p 올랐지만, 독립 원문 대조에서 두 문제가 드러났다.

- “이후 판단에서도 참여 가능성을 **확인해야 한다**”가 “이 조건을 함께 **봐야 한다**”로 바뀌어 확인 의무가 약해졌다.
- “이 안이 영구적인 운영 정책**으로** 확정된 것은 아니다”의 범위가 영구 정책 자체의 확정 여부로 넓게 읽힐 수 있었다.

두 표현을 복구하고 전체 원고를 다시 측정하자 76.3036%가 나왔다. 따라서 81.7625%를 성공 결과로 발표하거나 의미 오류가 있는 원고를 최상본으로 채택하지 않았다. 기존 80.1151% 원고를 유지하며 복구본은 대안으로 남겼다. 이는 기존 상용 검사에서 보관한 원고와 같은 바이트지만, 과거 상용 수치를 새 로컬 측정처럼 취급하지 않는다.

### 새 원문: 가독성과 탐지 점수가 함께 움직이지 않음

다른 세션에 새 작업실 공지와 스킬만 제공했다. 도입부의 추상 명사 표현을 풀고, 예약 일정과 사후 평가 절차를 구분해 썼다. 작성 세션은 원문 4개·수정문 5개 문단을 검토하고 13개 의미 대조를 수행했다. **별도의 검토자는 모델 점수와 작성자의 평가를 보지 않은 채** 조건·시점·의도·말투 보존 및 실제 읽기 개선을 확인했다.

Human은 95.8120%에서 85.9246%로 낮아졌다. 이를 점수 개선이라 부르지 않는다. 원문은 높은 점수의 복원 지점으로, 수정문은 독자에게 더 명확한 결과물로 각각 남겼다. 원문 점수를 수정문에 재사용하지 않았다.

### 영어: 실패를 성공으로 대체하지 않음

설치된 감독 실행기의 native worker가 `3221225477`로 두 번 종료했다. 두 번째 실행의 [오류·종료 기록](development/en-baseline-retry/execution.json)과 [확률 null 결과](development/en-baseline-retry/feedback.json)를 보존했다. 첫 실패는 터미널에서 관찰됐으며 모델 결과 파일이 생성되지 않았다. 실패 원인을 확정하거나, 영어 모델의 안정성이 입증됐다고 주장하지 않는다.

탐지기 지침에 따른 전체 문단 검토는 계속했다. “24-request denominator”를 일반 독자에게 표본 규모가 바로 드러나도록 한 문장만 고쳤다. 보고 의무·24건·중앙값 비교와 나머지 문단은 보존됐고, 독립 대조에서 추가 수정 사유는 없었다. 후보에는 새 수치 실행을 하지 않았다. 원문의 실행 실패를 후보의 실제 실행 기록으로 잘못 표시하지 않는다.

## 검증 범위와 한계

- 개발 위치에서 로컬 회귀 테스트 **81개 통과**: 기존 45개와 새 연결 도구 36개. 배포 폴더에서 재실행한 81개 중 **80개 통과, 1개는 개발 전용 원문 경로가 없어 건너뜀**이다. 실제 한국어 파이프라인에서 BOM·CRLF·결합 문자·이모지의 바이트 보존을 확인했다. 영어 정상 결과 검사는 합성 계약 fixture이며, 영어 추론 성공을 뜻하지 않는다. 모델이 설치되지 않은 CI에서는 실제 로컬 모델 검사도 건너뛰어질 수 있다.
- 탐지기 ledger **7개, 총 35개 문단 단위**를 실제 `evidence.py`로 검증했다. 해시·인용·좌표·검토 범위 검사이며 해석의 진위나 저자를 증명하지 않는다.
- 독립 세션의 도구 감사, 개발 원고 대조, 새 원문 적용 및 점수를 보지 않은 새 원문 품질 검토를 수행했다. 모두 AI 검토이며 인간 평가가 아니다. 문서를 반복 수정한 개발 실험으로, 통계적 교차검증·대표 표본·미사용 검증셋의 성능 추정이 아니다.
- 한국어 모델은 에세이·초록·시를 기준으로 보정됐다. 여기의 업무 문서는 평가 장르 밖이며, 도서관 문서는 학습 길이 중간 90% 범위(210–907자)도 벗어난다. 모델의 50% AI 기준 사전비율은 사용자의 실제 작성 비율이 아니다.
- 모든 평가 글은 AI 생성·편집 합성 표본이다. 로컬 Human 50% 이상인 결과가 나왔어도 “완전히 사람이 쓴 글”이나 모든 탐지기의 50% 이상 판정을 보장하지 않는다.
- 기존 **상용 검사 179건**과 원고별 최상본은 그대로 보존했다. 이번 단계의 상용 전이 성능은 측정하지 않았다. 영어 모델 실패와 반복 수정의 한계 때문에 무한 재검사를 계속하지 않았다.

v1.7.0은 요청한 로컬 피드백 활용 기능으로 채택한다. 범용 탐지 성능 향상이 입증됐다는 이유로 채택하는 것이 아니다. 이전 [v1.6.0 24개 파일](retained-skill/)과 배포 기록은 복원 가능하다.

[최종 독립 배포 감사](release-review.md)에서 오래된 테스트 설명과 검증 기록의 일치 검사 누락을 찾아 고쳤다. 수정 후 점수·실패 결과·인용·원문 해시·원문 바이트·문단 검토 누락·검증 보고서 인용 변조 **7건 모두 거부**, 정상 복사본은 통과했다. [검사 결과와 초기 실패 이력](release-negative-checks.json), [복제 저장소에서 실행할 재검사 도구](release-negative-checks.py)를 포함한다. 재검사 도구는 `--out`으로 고정 증거 폴더 밖에 새 결과를 저장하며 기존 감사 기록을 덮어쓰지 않는다.

## 탐지기 제작 세션에 오류 전달

사용자의 명시적 요청에 따라 `AI detector skill 만들기` 세션에 영어 입력 해시, 감독 실행 명령, native 종료 코드와 두 번째 실패 기록의 위치를 전달했다. 해당 세션이 오류 분석을 시작한 것을 확인했다. 탐지기 수정 작업과 humanizer 개선은 별도로 진행하며, 수정 완료나 영어 성공 재측정으로 표시하지 않는다. 모델 변경으로 점수를 올리는 작업을 요청한 것이 아니며, 출력 계약 변경 시 연결 도구도 다시 검토한다.
