# v1.9.0 release audit

The exact staged release is ready under this audit's scope. The package, evidence bindings, documentation claims and installation preflight passed. This finding does not mean the Human >=50% target was achieved; that target remains unmet on all three retained native-score checkpoints.

## Reviewer role and limits

This reviewer was independent of the parent's release implementation but previously wrote the v1.8 baseline candidates. This is therefore a limited implementation and artifact audit, not a fresh independent assessment of candidate prose. Another agent performed the score-blind paired reader review. I used final candidate bytes for copying, hashing and machine validation only; I did not reassess their prose or select a preferred rewrite.

The earlier instruction audit found no actionable semantic, register or unsupported-performance-claim issue in the new English guidance. Its four verifier findings were repaired and tested here. No inference, network call, payment, publication or real installation occurred during this release audit. All corruptions were confined to a disposable fixture; an explicit write guard prevented the installer probes from copying files to any installed directory.

## Completed checks

- The unit suite ran 81 tests: 80 passed and one was skipped. The complete offline evidence gate passed, including nine native English measurements, nine complete anchored document reviews, source and candidate hash bindings, blinding declarations, eligibility, chronology, selections and retained releases.
- The staged instruction tree and repository skill match the 30-file release manifest. The v1.9.0 ZIP has exactly 30 unique entries, the required root prefix, valid CRCs and identical uncompressed file hashes. The 28-file v1.8.0 ZIP and retained skill match the previous release manifest byte-for-byte.
- Compared 976 historical benchmark files with the saved pre-v1.9 repository archive; none changed. The historical machine gates validate all 179 commercial observations. This audit checks local preservation and consistency, not vendor authenticity.
- Checked local links in 26 relevant documents. No unexpected missing target was found. The report's release-review link is fulfilled by this audit artifact when it is copied into the public evidence folder.
- The reported percentages match the native Human-only values, experimental candidates exceed baseline values in 3/3 cases, and the recorded >=50% target is false. The documentation retains the mixed reader preferences, source-review context asymmetry, uncalibrated detector limitation, synthetic origin and absence of new commercial calls. It does not claim an overall naturalness win or general detector improvement.
- Assembly rejects `--install`. The separate installer requires a true audit result bound to the exact repository payload, checks staged instructions, runs the full evidence gate, validates the ZIP, and only then reaches installed-file copying. Optimized Python is rejected by the verifier and installer.

## Mutation checks and repaired defect

Twenty-nine negative probes were rejected after repairs. Evidence mutations were re-frozen so rejection tested the structural checks rather than only the outer manifest. Cases included empty or duplicate selections, duplicate or mislabeled measurements, wrong candidate and review bindings, duplicate reviews, empty/incomplete execution calls, wrong script hashes, disabled assertions, a false 50% target claim, a non-Boolean target, native document/window class disagreement, a blinding breach, wrong eligibility-review hash and scoring before authorization.

Installer probes also rejected missing readiness, a stale payload digest, a changed repository, changed staging instructions, invalid evidence despite a matching digest, optimized execution, assembly installation requests, and malformed ZIPs. The initial ZIP implementation accepted a duplicate entry because a dictionary comparison collapsed duplicates. This was reported, repaired by explicit count/uniqueness/prefix checks, and retested with duplicate entries, a wrong prefix and changed file contents. Each now fails before any installed write. No unresolved blocker remains.

The final machine gate was run after artifact and mutation checks. Exact audit artifacts were also copied into the disposable fixture, its manifest refreshed, and the full gate rerun. The actual repository and release ZIP remained unchanged throughout the audit.
