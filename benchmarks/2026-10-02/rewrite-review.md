# 네 문안의 재작성·검토 기록

## 범위와 방법

- 대상: `corpus`의 `en-library`, `ko-library`, `en-cache`, `ko-cache` 원문 네 개.
- 요청: 원문 언어와 격식, 모든 사실·조건·제한·말뜻을 보존하면서 문장과 구조를 적극 재작성한다. 원문 파일은 수정하지 않는다.
- 적용 스킬: `$CODEX_HOME/skills/bilingual-humanizer/SKILL.md` (1.1.0). `iterative-review.md`, `english.md`, `korean.md`, `genres-and-voice.md`, `fidelity-and-documents.md`를 실제로 읽었다.
- 네 문안은 각 원문에 독립적으로 대응한다. 한국어와 영어 사이의 원래 차이를 번역으로 통일하지 않는다.
- 웹 검색, 외부 업로드, AI 탐지기를 사용하지 않았다. 이 기록은 문안의 편집·보존 검토이며 저자성이나 탐지 성능을 평가하지 않는다.

## 실제 작업 단계

1. 네 원문을 읽고 최초 SHA-256을 기록했다.
2. 최초 후보 v1을 작성했다. 도서관 문안은 의견서에 나타난 선호와 실제 방문의 차이를 연달아 읽도록 재배열하고 5문단으로 나눴다. 캐시 문안은 수치를 먼저 제시하고 증거의 범위, 운영 판단, 승인 상태를 차례로 설명했다. 뜻 없는 반복은 합쳤고 문장별 주장과 제한은 남겼다.
3. v1을 원문과 대조한 자체 의미 검토와 독자 검토를 실시했다. 아래의 구체적인 문제를 찾아 3개 파일을 1회 수정했다. 한국어 캐시에는 수정할 결함을 찾지 않아 v1을 유지했다. v1의 정확한 텍스트는 `rewrite-history/v1`에 보존했다.
4. 수정 후보 v2를 다시 원문과 대조하고 독자 관점으로 읽었다. 수치와 단위는 설치 스킬의 오프라인 `audit_preservation.py`로도 확인했다. 네 실행 모두 종료 코드 0, `no_surface_change_found`, `review_candidates: []`였다. 이 표면 검사는 의미 검토를 대신하지 않는다.
5. 새로운 문맥의 별도 검토 에이전트 `commercial_blind_rewrite/fresh_reader`에 원문·후보·요청·스킬 위치만 전달했다. 자체 평가나 기대 답안, 외부 평가 결과는 전달하지 않았다. 검토자는 한국어 도서관 문안의 판단 강도 변화 1건을 보고했으며, 나머지 세 문안의 의미 보존과 네 문안의 자연스러움에서 수정이 필요한 결함을 찾지 못했다.
6. 해당 지적을 수용했다. 자체 검토에서도 영어 도서관 문안의 `cannot capture`가 자료의 불충분함보다 일반적인 불가능성을 뜻할 여지를 발견하여 함께 수정했다. 두 도서관 문안에 대한 두 번째 수정이다. 수정 전 v2 후보와 최초 오프라인 검사 결과를 `rewrite-history/v2`에 보존했다.
7. 변경된 두 후보를 다시 원문과 대조하고 전체 문장을 읽었다. 두 오프라인 보존 검사를 다시 실행했고 모두 종료 코드 0이었다. 캐시 후보는 바꾸지 않았으므로 첫 검사와 같은 파일이다. 같은 검토자에게 현재 네 후보의 후속 검토를 요청했다. 이는 두 번째 맹검이나 새로운 독립 검토자가 아닌 같은 검토자의 후속 검토다.
8. 후속 검토자는 두 도서관 후보를 전체 원문과 대조하고 독자 검토를 완료했다. 영어의 정보 한계와 한국어의 판단 강도가 원문에 맞게 보존되었으며, 한국어의 기존 지적은 해결됐다고 보고했다. 두 캐시 후보도 다시 확인해 기존의 '발견한 결함 없음' 판단을 유지했다. 작성자는 현재 네 후보 전체를 마지막으로 다시 읽었고 추가로 고칠 구체적인 결함을 찾지 못했다. 이후 문안은 수정하지 않았다.

## 실제 수정 이력

| 문안 | v1에서 발견한 구절 | 수정 내용과 이유 |
|---|---|---|
| 영어 도서관 | `The community library has proposed ...` | `The proposed pilot would keep the community library open ...`로 변경. 원문에 없는 제안 주체와 완료된 제안 행위를 보태지 않도록 했다. |
| 영어 도서관 | `favour`, `recognise` | 각각 `prefer`, `recognize`로 변경. 불필요하게 새로운 영국식 표기를 도입하지 않았다. |
| 한국어 도서관 | `지역 도서관은 ... 제안했다` | `지역 도서관의 시범 운영안은 ... 방안이다`로 변경. 명시되지 않은 제안 주체를 제거했다. |
| 한국어 도서관 | `아직 확인되지 않았다` | `아직 해결되지 않은 문제다`로 변경. 봉사자 가용성의 미해결 상태를 단순한 확인 여부로 바꾸지 않았다. |
| 한국어 도서관 | `열람실에 동시에 들어갈 수 있는 인원` | `열람실을 동시에 이용할 수 있는 인원`으로 변경. 열람실의 정원이 의미하는 이용 인원을 분명히 했다. |
| 영어 캐시 | `warrants further evaluation` | `is relevant to further evaluation`으로 변경. 원문의 참고 가치보다 추가 평가의 필요성을 강하게 주장하지 않도록 했다. |
| 영어 캐시 | `behaviour` | `behavior`로 변경. 원문의 `authorize`와 일관된 표기를 유지했다. |
| 한국어 캐시 | 구체적인 수정 필요 없음 | 최초 후보를 유지했다. 반복 검토를 했다는 이유만으로 문구를 바꾸지 않았다. |

두 번째 수정의 근거:

| 문안 | v2의 구절 | 수정 내용과 이유 |
|---|---|---|
| 한국어 도서관 | `모든 이용자의 요구를 그대로 나타내지는 않는다` | 독립 검토자의 중간 중요도 지적을 수용해 `모든 이용자의 요구를 그대로 나타낸다고 볼 수는 없다`로 수정했다. 대표성이 없다는 단정이 아니라 대표한다고 판단할 수 없다는 원문의 제한을 유지했다. |
| 영어 도서관 | `They cannot capture every library user's needs.` | 자체 검토 후 `They do not give a complete account of every library user's needs.`로 수정했다. 자료가 완전하지 않다는 원문의 설명을 일반적 불가능성으로 넓히지 않았다. 독립 검토자의 영어 결함 지적이 있었던 것은 아니다. |

## 원문 의미 대조

도서관 원문 두 개에서 각각 확인한 공통 항목:

- 화요일·목요일 저녁, 20:00까지, 6주간이라는 운영 범위와 아직 제안 단계라는 상태.
- 일시적인 시범 운영이며 영구 정책이 아니라는 구분, 향후 상시 일정에 대한 별도 논의.
- 의견서 총 42건과 연장 지지 28건·현재 일정 선호 9건·선호 없음 5건의 관계.
- 수치는 제출된 의견의 분포이며 전체 이용자의 요구로 확대할 수 없다는 제한.
- 연장을 지지하는 의견과 현재 일정을 선호하는 의견을 모두 고려한다는 취지.
- 자원봉사자 가용성의 미해결 상태와 운영 시작 뒤로 미루기 어려운 조건이라는 판단.
- 조용한 열람실 정원 12, 시간 연장이 공간을 늘리지 않음, 안내에서 이용 시간과 공간을 구분해야 함.
- 선호의 표현은 실제 방문의 증거가 아님. 개관 시간 연장이 방문 증가를 일으킨다는 인과적 근거가 현재 자료에 없음.
- 이후 결정에서는 관심을 인정하되 자원봉사자 확보를 명확히 하고 영구 변경과 구분함.

언어별로 다른 원문의 내용도 보존했다. 영어 원문의 현재 일정 선호 이유를 고려한다는 구절과 어느 집단도 전체를 대표한다고 가정하지 말라는 구절은 영어 후보에 남겼다. 한국어 원문의 응답 수만으로 선호 이유를 알 수 없다는 경고, 안내에서 임시·상시를 구분하라는 요구, 결정 문서가 영구 변경을 확정한 것으로 읽히지 않도록 표현을 점검하라는 요구는 한국어 후보에 남겼다.

캐시 원문 두 개에서 각각 확인한 공통 항목:

- 가상의 시험을 검토하는 메모라는 범위와 실제 운영 환경 도입 전의 검토라는 목적.
- 48회 실행, 지연 시간 중앙값 120ms에서 90ms, 메모리 사용량 256MB에서 288MB라는 수치와 대상.
- 지연 시간과 메모리를 함께 제시·평가해야 하며 지연 시간만 강조하면 메모리 증가가 누락됨.
- 중앙값은 모든 실행을 나타내지 않음. 전체 분포가 제공되지 않았고 일관성·예외 상황을 임의로 보태면 안 됨.
- 메모리 증가는 절충 관계를 나타내지만 수용 여부에는 운영 환경의 맥락이 필요하고 요약만으로 충분하지 않음.
- 모바일 클라이언트 제외와 그 동작에 대한 판단 유보, 실제 시험 범위 유지.
- 관찰된 관계는 상관관계이며 운영 환경에 대한 인과 증거가 아님. 서비스 이익이나 시험하지 않은 조건에서의 동일한 지연 시간·메모리 관계를 확정할 수 없음.
- 운영 환경 도입 미승인. 롤백 조건은 실패율이 2%를 **초과**하는 경우이며 후속 검토에서도 명시해야 함.
- 롤백 규칙의 존재가 배포 승인이나 증거의 한계 해소를 대신하지 않음.
- 다음 결정은 두 측정값과 시험 범위를 함께 고려하고 결과 해석과 승인을 별도로 판단함.

한국어 원문의 추가 지시인 '요약에 없는 조건을 확인된 사실처럼 보태지 않기'와 '긍정적인 수치와 한계를 함께 전달하기'도 한국어 후보에 명시적으로 남겼다.

## 최종 파일 확인

공백으로 구분한 비어 있지 않은 문자열(`\S+`)을 한 단위로 셌다. 영어는 공백 기준 단어수, 한국어는 공백 기준 어절수다. 의미나 저자성을 판정하는 지표가 아니다. 모든 원문과 후보는 UTF-8 BOM 없음·LF 형식이다. 최종 원문 해시는 처음 읽었을 때와 모두 일치한다.

| 파일 | 공백 단위 | 문단 | SHA-256 |
|---|---:|---:|---|
| en-library-source.txt | 302 | 4 | `bdcb854f5676ebff48f3a958d11ae3209ee42f8ece11f4ba933488c6d0b6029f` |
| en-library-rewrite.txt | 291 | 5 | `fef71e4e895e4812177fba7547b1ad59d3dfa31d91105cc659e6e77446670883` |
| ko-library-source.txt | 264 | 4 | `b82f92389cf1c42ded62184eb359c87d81848723d44a2b9790b9fa0eb6dfd5b0` |
| ko-library-rewrite.txt | 236 | 5 | `e186f38964e62b2f34802d51778243348bd2535528233f9f0f5216a118b43504` |
| en-cache-source.txt | 302 | 4 | `4411dc7c9875e0a6455d3dc9a1790e68ea371f38d2a750599b2444c9bc2ec509` |
| en-cache-rewrite.txt | 264 | 4 | `c416a7a31fa3f9db8c350e2a88b24b3cec02adf468d1ff015766e38ae1cfd11a` |
| ko-cache-source.txt | 264 | 4 | `8c6997b3b5a9bce066216fa41bd84feeb357975e7ec1e6cf51bd7765dfa7dc7b` |
| ko-cache-rewrite.txt | 227 | 4 | `6ab3ea3cec5b19a24b5aa6abfb4e884aa310f40475b8ffe84c04a4d593258e2c` |

기계 판독용 파일 목록은 `rewrite-manifest.json`, 최종 후보별 수치·단위 표면 검사 기록은 네 `*-preservation-audit.json`이다.

## 완료 상태와 검토 횟수

- 작성자의 자체 의미 대조·독자 검토: v1, v2, 최종 후보에 대해 세 단계 수행. 같은 작성자의 자체 검토이며 독립된 세 세션으로 계산하지 않는다.
- 별도 에이전트 검토: 새 문맥 검토 1회, 같은 검토자의 후속 검토 1회. 별도 사람이나 다른 모델의 검증으로 주장하지 않는다.
- 실제 수정 사이클: 최초 후보 이후 총 2회. 파일별로 영어 도서관 2회, 한국어 도서관 2회, 영어 캐시 1회, 한국어 캐시 0회.
- 오프라인 표면 검사: 첫 후보 검토 후 4건, 두 번째 수정 후 변경 파일 2건 재검사. 최종 후보 네 개에 대응하는 기록은 모두 수치·단위 등 인식 범위에서 변경 후보 없음이다.
- 최종 자체 검토와 별도 검토자가 보고한 미해결 결함: 없음. 이는 가능한 모든 결함의 부재를 증명하는 주장은 아니다.
- 외부 AI 탐지기 실행: 0회. 탐지 점수, 저자성, 특정 탐지기 통과 여부에 관한 결론은 내리지 않았다.
- 종료 이유: 요청된 구조·문장 재작성과 실제 발견된 의미 보존 문제의 수정, 최종 독자 검토가 끝났다. 구체적인 결함 없이 남은 수정 예산을 소모하지 않는다.
